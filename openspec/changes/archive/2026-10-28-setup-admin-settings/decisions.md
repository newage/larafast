# Журнал рішень: розділ Setup в адмінці (налаштування Claude)

## Проблема
Параметри Claude-чату (ключ, модель, effort, ліміти, поріг векторного пошуку) задаються лише в `.env`. Щоб їх змінити, потрібен доступ до сервера і деплой, тож власник сайту не може підкрутити їх сам з адмінки.

## Дано
- Filament 5 на `/admin`, `AdminPanelProvider` має `discoverPages(app/Filament/Pages)`; сторінок і ресурсів ще немає — перевірено: `app/Providers/Filament/AdminPanelProvider.php`, `app/Filament`.
- У БД лише `users`, `cache`, `jobs`; моделі `settings` немає — перевірено: `database/migrations`, `app/Models`.
- Жоден код не читає ці 7 параметрів: чат клієнтський, відповіді за ключовими словами — перевірено: `resources/js/chat.js`, grep по проєкту. Споживач (живий чат) — окрема майбутня зміна.
- Не обговорюється: розділ називається Setup, інтерфейс польською, у `settings` рівно 7 параметрів із `.agents/propose/setup_admin.md`.
- Зразок конфігу з `env()` — `config/site.php`.
- Домен: один контекст (адмінка/конфігурація), агрегатів немає.

## Концепт рішення
**Обрано:** таблиця `settings` у БД; значення з БД перекривають `.env`-дефолти; редагування на сторінці Setup у Filament.
**Чий:** запропонував розробник (таблиця + сторінка); шар перекриття над `.env` обрано у воронці.
**Чому:** `.env` лишається дефолтами для нових середовищ, а адмін міняє значення без деплою; порожнє поле означає «взяти з `.env`».
**Відкинуто:**
- Лише БД, `.env` не читається — дефолти довелося б дублювати в коді/сідері.
**ADR:** ні — легко змінити, меж контекстів не перетинає.

## Вектор
```
Filament /admin ──► Setup (page, PL) ──► запис ──► settings (key, value)
                                                        │
споживач (майбутній) ──► читання ключа ──► рядок у settings? ──так──► значення з БД
                                                    └─ні/порожнє─► config()/env() дефолт
```
- Один рядок у `settings` на параметр; ключі збігаються з назвами з `.env`.
- Читання: рядок із непорожнім значенням → БД, інакше → дефолт із `.env` через `config`.
- Споживача в цій зміні немає: вона лише зберігає й редагує значення.

## Деталі
### Збереження й показ ANTHROPIC_API_KEY
**Рішення:** значення шифруються (`encrypted`), у формі показується лише маска (`sk-ant-…x7Qf`), нове значення замінює старе, порожнє поле лишає збережене.
**Чому:** ключ є секретом; витік БД чи скріншот форми не повинні його розкривати.
**Альтернатива:** звичайне поле з відкритим текстом — відкинуто через ризик витоку.
**ADR:** ні — локальне рішення в межах однієї таблиці.

## Відкриті питання
- Де саме тримати дефолти поза `.env` (наприклад, `config/claude.php`) і які назви ключів — вирішується на етапі `propose` за зразком `config/site.php`.

## Припущення
- Валідація: `CLAUDE_EFFORT` — вибір зі списку `low|medium|high|xhigh|max` або порожньо; числові параметри — цілі додатні; `VECTOR_MIN_SCORE` — число від 0 до 1; `CLAUDE_MODEL` — довільний рядок. Не блокує.
- Усі підписи й повідомлення сторінки Setup польською, пункт у меню «Setup». Не блокує.
- Кешування читання не потрібне, споживача ще немає. Не блокує.
