# Журнал рішень: карусель плиток у розділі Realizacje

## Проблема
У розділі «Realizacje» 3 плитки проєктів у сітці на 3 колонки. Додається 4-й проєкт (Nordleaf), згодом 5-й. Сітка 3+2 розсипається, секція росте вниз, а кількість плиток стає непередбачуваною для вертикальної верстки.

## Дано
- Плитки — масив `$projects` (6 полів: meta, name, text, tags, url, host) — перевірено: `resources/views/components/projects.blade.php:2`
- Стилі `.projects` (grid 3 кол.) і `.proj` — перевірено: `resources/css/app.css:224-231`; адаптив 3→2→1 колонка: `app.css:316`, `app.css:328`
- JS: лише `resources/js/app.js` і `chat.js`, каруселі/бібліотек слайдерів немає — перевірено: `ls resources/js`
- Новий проєкт: Nordleaf, `https://nordleaf.vadymleontiev.dev/`, Astro · TypeScript · Decap CMS, у розробці; ставиться **першим** — перевірено: `.agents/propose/carousel.md`
- Опис польською (джерело): «Nordleaf to jednostronicowa witryna sklepu z roślinami i donicami. Klienci mogą zobaczyć ofertę roślin, donic i zestawów oraz wysłać zapytanie ze zdjęciem. Właścicielka sama edytuje treści i zdjęcia w prostym panelu.»
- Не чіпаємо: незакомічена правка тегів `rag · node.js` у плитці vadymleontiev.dev
- Правила `.ai/rules/views.md` (Setting::resolve) не стосуються цієї зміни

## Концепт рішення
**Обрано:** CSS scroll-snap зі стрілками ‹ › (невеликий JS у `app.js`), без залежностей
**Чий:** згенеровано у воронці (у розробника ідеї не було)
**Чому:** явна навігація на десктопі без нової залежності й ваги.
**Відкинуто:**
- Лише scroll-snap без стрілок — на десктопі не видно, що є ще плитки
- Swiper — нова залежність (потрібне погодження) і вага ~40 КБ заради 4–5 плиток
**ADR:** ні — легко оборотне, локальна зміна UI

## Вектор
```
$projects (Blade) ──► .projects (flex, overflow-x, scroll-snap)
                          ▲
 кнопки ‹ › ── app.js ────┘  scrollBy(ширина плитки)
```
- Дані залишаються в Blade-масиві; Nordleaf додається першим елементом.
- Розкладка змінюється з grid на горизонтальний ряд зі scroll-snap.
- Кнопки зсувають ряд на ширину плитки; JS лише керує scroll.
- Існуючий адаптив (3→2→1) замінюється кількістю видимих плиток на ряд.

## Деталі
### Позначка «у розробці»
**Рішення:** у полі `meta` плитки Nordleaf (напр. «w trakcie · sklep roślin»), без нового поля й стилів.
**Чому:** не змінює структуру даних; поле `meta` уже несе статус-подібні підписи.
**Альтернатива:** бейдж — відкинуто, нове поле й CSS заради одного проєкту.
**ADR:** ні — тривіально оборотне

## Відкриті питання
- Точна польська формула `meta`/`tags` для Nordleaf — уточнити при реалізації (теги: `astro · typescript · decap cms`).

## Припущення
- Видимих плиток на десктопі 3, планшет 2, мобільний 1 (зберігаємо поточні брейкпоінти).
- Стрілки неактивні (disabled) на краях ряду; автопрокрутки немає.
- Кнопки мають `aria-label` польською («Poprzednie»/«Następne»), доступність з клавіатури через нативний фокус кнопок.
- Тести не потрібні: зміна лише верстки/JS без бекенд-логіки.
