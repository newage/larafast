# Журнал рішень: FAQ-чат (PHP/Laravel, POST /chat)

## Проблема
Польськомовні відвідувачі сайту не мають способу швидко отримати відповідь про послуги й ціни: FAQ лежить лише в `data/faq.json`, а вільний LLM-чат вигадував би зайве. Без змін питання йдуть у ручну переписку.

## Перегляд: Python → PHP (2026-11-02)
**Рішення розробника:** весь код (сервіс, сидер, вимірювач порога) переписано з Python/FastAPI/LangChain на PHP; Python прибрано з Docker.
- Claude: пакет `anthropic-ai/sdk`. Pinecone: звичайні HTTP-запити (`Http::`), без SDK.
- Де живе код: усередині Laravel (контролер + `app/Faq/`), окремий контейнер `ai-service` видалено. Альтернатива «окремий PHP-контейнер» відкинута: другий PHP-образ і дубль інфраструктури без користі.
- Наслідки: `location /chat` і `limit_req` у nginx не потрібні (запит іде в php-fpm), rate limit — `throttle` Laravel; сидер і вимірювач — artisan-команди `faq:seed`, `faq:measure-score`; параметри Claude беруться через наявний `Setting::resolve()`.
- Межі зміни розширено: `app/`, `routes/`, `bootstrap/`, `config/services.php`, `composer.*`; `docker/*` не змінюється.
- Поведінка (специфікації `faq-chat`, `faq-index`) не змінилась, крім механізму rate limit (nginx → Laravel) і способу запуску команд.
- Усе нижче в цьому файлі про Python, FastAPI, LangChain, `ai-service` і nginx-проксі — історія початкового варіанту; чинний варіант описано в `design.md` і `tasks.md`.

## Дано
- Docker: `php`, `nginx`, `mysql`, `node` — перевірено: `docker/docker-compose.yml`; Nginx проксує лише на php-fpm — `docker/nginx/default.conf`.
- `.env.example` вже містить `CLAUDE_*`, `MAX_MESSAGES`, `MAX_MESSAGE_CHARS`, `VECTOR_MIN_SCORE`, `PINECONE_*` (незакомічено) — перевірено: `git diff .env.example`.
- `data/faq.json`: 29 записів, 101 питання, поля `parent_id`, `type` (web/ai/general), `text`, `questions`; польською — перевірено: аналіз файлу.
- Приклад сидера (JS): 1+N чанків на запис (чанк 01 = `text`, 02.. = по питанню), `answer` = оригінальний текст, ідемпотентність через `content_hash`, батчі по 96 — `.agents/propose/seed-pinecone.js`, `seed-lib.js`. Поля `lang`, `project` прибрані.
- `measure-score.js`: leave-one-out по питаннях FAQ + фіксований off-topic набір, таблиця порогів; rerank-гілка й імпорти `../src/*` відсутні в репо — `.agents/propose/measure-score.js`.
- Фіксовано ТЗ: Python + FastAPI + LangChain, `POST /chat`, Nginx reverse proxy, Pinecone, `claude-haiku-5-5`, відповідь `{"type":"answer","message":"..."}`, системний промпт польською — `.agents/propose/ai-service.md`.

## Концепт рішення
**Обрано:** B — перед пошуком окремий виклик Claude перетворює останнє питання (з урахуванням історії) на самодостатнє; Pinecone шукає по ньому; далі другий виклик Claude: знайдений контекст + історія + оригінальне питання.
**Чий:** запропонував розробник (початково A; переглянуто на B після розбору слабкості follow-up-питань з займенниками)
**Чому:** «A ile to kosztuje?» після розмови про chatbota без переформулювання шукається в Pinecone без теми й дає не той запис або нічого.
**Відкинуто:**
- A (пошук по сирому останньому питанню, початковий варіант ТЗ) — follow-up-питання з займенниками втрачають тему; фіксована фраза «не знайдено» спрацьовує до Claude, і історія вже не допомагає.
- C (вся FAQ у системному промпті, без Pinecone) — токени на кожен запит, не масштабується, ламає ТЗ про Pinecone/seed/measure-score.
**ADR:** ні — сервіс ізольований; переформулювання — окремий крок, який вимикається одним рядком.

## Доменна модель
- **Контексти:** `ai-service` (новий, ізольований, stateless) — єдиний; Laravel не зачіпається, окрім `docker/nginx/default.conf`. Межа зміни: `ai-service/`, `docker/docker-compose.yml`, `docker/nginx/default.conf`, `.env.example`.
- **Терміни:** FAQ-запис = `parent_id` + `text` + `questions`; чанк = один рядок в індексі (`{parent_id}-NN`); «знайдено» = чанк зі score ≥ `VECTOR_MIN_SCORE`; запис = унікальний `parent_id` серед знайдених чанків.
- **Агрегати й інваріанти:** FAQ-запис — чанки завжди будуються з одного запису; `answer` в усіх чанках = оригінальний `text`. Запит: останнє повідомлення без `answer`, попередні (≤ `MAX_MESSAGES`-1) з `answer`.
- **Транзакційні межі:** немає (сервіс stateless); запис у Pinecone — лише сидер, батчами, ідемпотентно через `content_hash`.

## Вектор
```
Браузер ─▶ nginx (limit_req) ─┬─ /chat ──▶ ai-service (FastAPI)
                               │             1. валідація
                               │             2. переформулювання: len(messages)>1 ─▶ Claude(історія + питання) ─▶ самодостатнє питання;
                               │                одне повідомлення ─▶ питання без змін
                               │             3. Pinecone.search(самодостатнє питання), групування за parent_id, ≤3 записи ≥ VECTOR_MIN_SCORE
                               │             4a. порожньо ─▶ фіксована польська фраза (без другого виклику Claude)
                               │             4b. знайдено ─▶ LangChain(Claude): контекст + історія + оригінальне питання ─▶ {"type":"answer","message":"..."}
                               └─ решта ──▶ php-fpm (Laravel)
CLI в образі ai-service: seed.py · measure_score.py ─▶ Pinecone
```
- `ai-service` stateless: історію присилає клієнт, нічого не зберігаємо.
- На запит до двох викликів Claude: переформулювання (лише коли є історія) і відповідь.
- Pinecone у рантаймі лише читаємо; запис тільки сидером.
- `/chat` обслуговується існуючим nginx у тому ж vhost (той самий origin, без CORS).
- Seed і measure-score — CLI-скрипти, не частина API.

## Деталі
### Маршрутизація /chat
**Рішення:** існуючий nginx, `location /chat` → `ai-service`.
**Чому:** один origin, без CORS, без зайвого контейнера.
**Альтернатива:** окремий nginx на своєму порту — потрібен CORS і ще контейнер.
**ADR:** ні — легко змінити.

### Переформулювання питання
**Рішення:** якщо в `messages` більше одного елемента, окремий виклик Claude з історією й останнім питанням повертає одне самодостатнє питання польською; воно йде в Pinecone. Одне повідомлення — переформулювання пропускається.
**Чому:** без цього follow-up-питання з займенниками шукаються без теми; перше питання не платить за додатковий виклик.
**Альтернатива:** пошук по сирому питанню (A) — слабкі follow-up; конкатенація попереднього питання з поточним — шумніше, але без виклику.
**ADR:** ні — окремий крок у пайплайні.

### Відповідь, коли нічого не знайдено
**Рішення:** фіксована польська фраза «не маю інформації», другий виклик Claude (відповідь) не робиться; формат `{"type":"answer","message":"..."}`.
**Чому:** 0 токенів, детерміновано, нічого не вигадується.
**Альтернатива:** Claude з порожнім контекстом — платимо за off-topic, ризик вигадок.
**ADR:** ні — одне місце в коді.

### Скільки записів іде в Claude
**Рішення:** чанки групуються за `parent_id`; до 3 унікальних записів зі score ≥ `VECTOR_MIN_SCORE`; в контекст іде `answer` кожного.
**Чому:** складні питання зачіпають кілька записів (ціна + строки), вартість мала.
**Альтернатива:** лише top-1 — неповні відповіді на складні питання.
**ADR:** ні — константа в коді.

### Rate limit
**Рішення:** `limit_req` у nginx по IP на `/chat`: 10 запитів/хв, burst 5, понад — 429.
**Чому:** публічний ендпоінт платить за токени Claude.
**Альтернатива:** без захисту — відкритий бюджет.
**ADR:** ні — значення в конфігу nginx.

## Відкриті питання
- Якість переформулювання: модель може додати зайве або спотворити питання; `measure_score.py` перевіряє лише одиночні питання, багатокрокові розмови не покриває — повернутись після перших живих діалогів.
- Точний текст фіксованої польської фрази — формулюється при реалізації, не блокує.

## Припущення
- Помилки: невалідне тіло (>`MAX_MESSAGES`, довге повідомлення, останнє з `answer`, попереднє без `answer`, порожнє питання) → HTTP 422; збій Claude/Pinecone → HTTP 502; тіло помилки `{"type":"error","message":"..."}` — non-blocking.
- Claude викликається через `langchain-anthropic`; `CLAUDE_MODEL`, `CLAUDE_MAX_TOKENS`, `CLAUDE_EFFORT` (порожнє = дефолт API) з env — non-blocking.
- Переформулювання: та сама `CLAUDE_MODEL`, окремий короткий промпт («поверни лише самодостатнє питання польською, нічого не додавай»), `max_tokens` малий (~128), без `CLAUDE_EFFORT` вище low; при збої цього кроку — деградація до сирого питання (поведінка A), а не 502 — non-blocking.
- Rate limit: тепер до двох викликів Claude на запит; ліміт 10/хв з burst 5 лишається — non-blocking.
- Системний промпт відповіді: відповідати польською, нічого не вигадувати, дані лише з контексту, інше не відповідати — за ТЗ.
- Структура: `ai-service/` у корені репо (`app/` — FastAPI, `scripts/seed.py`, `scripts/measure_score.py`, `Dockerfile`, `requirements.txt`); `data/faq.json` монтується в контейнер; скрипти запускаються через `docker compose exec` — non-blocking.
- Сидер Python — порт `seed-pinecone.js`/`seed-lib.js` без `lang` і `project`; `content_hash` = sha256 від `[embedded, answer, type]`; нічого не видаляє. `measure_score.py` — порт `measure-score.js` без rerank-гілки (немає `RERANK_MODEL` в конфігу) — non-blocking.
- `PINECONE_NAMESPACE` порожнє → `__default__`; `PINECONE_INDEX_NAME` у `.env.example` — `develop`, у ТЗ — `faq`; значення задає `.env`, код читає env.
- Ліміт довжини: `MAX_MESSAGE_CHARS` застосовується до кожного `question` і `answer`.
